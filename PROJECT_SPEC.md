Avoid overly polished patterns, excessive abstraction, or enterprise-grade architecture that a student wouldn't naturally produce. Use clear variable names and straightforward logic. Add comments where a student would — to explain tricky parts, not to document the obvious. Keep the code clean and well-organized, but don't over-engineer. A student writes practical, working code — not showcase code. ### Security First

Every piece of code in this project must be written with security as a primary concern. Never hardcode secrets, API keys, passwords, or credentials — always use environment variables via `.env`. Validate and sanitize all user input before processing. Use parameterized queries for database access — never concatenate user input into SQL strings. Implement proper authentication and authorization checks on every protected route. Set appropriate CORS policies, use HTTPS everywhere, and follow the principle of least privilege. When in doubt about a security decision, choose the more restrictive option. Review the OWASP Top 10 and ensure none of those vulnerabilities are present.
